# 디자인 브리프 — 현재 구현 "브리핑 도크"

`../index.html`에 적용된 디자인의 근거와 토큰. 다시 만들 때 **따라도 되고 버려도 된다.**
버릴 거라면 최소한 §4(비타협 요건)만은 지켜야 한다.

---

## 1. 문제 정의

이 사이트는 **한 사람이 두 상황에서만 쓴다.**

| 상황 | 필요한 것 | 디자인 함의 |
|---|---|---|
| 강의 전날 밤, 책상에서 정독 | 장시간 가독성, 흐름, 밀도 조절 | 본문 폭 제한, 넉넉한 행간, 저채도 배경 |
| 강의 중 Q&A, 30초 안에 검색 | 즉시 찾기, 즉시 판독 | 전역 검색, 강한 위계, 표 우선 |

**하지 않는 것**: 설득, 전환, 브랜딩. 이 문서는 아무것도 팔지 않는다.

따라서 랜딩페이지 문법(히어로→소셜프루프→CTA)을 전부 버리고, **계기판이 달린 매뉴얼**로 접근했다.

## 2. 컨셉 — 브리핑 도크

관제실에 붙어 있는 브리핑 문서. 잉크블랙 바탕, 한 가지 신호색, 계기처럼 정렬된 숫자.
장식이 아니라 **상태 표시**로만 색을 쓴다.

세 가지 결정:

1. **단색 강조.** 앰버 하나만. 여러 색이 경쟁하면 "이게 중요한가?"를 매번 판단해야 한다. 색이 하나면 앰버 = 주의, 그 외 = 본문으로 학습이 끝난다.
2. **메타데이터는 전부 모노스페이스.** 날짜·등급·권 번호·수치는 sans가 아니라 mono로 조판했다. 본문과 데이터가 시각적으로 분리되어 스캔이 빨라진다.
3. **여백 레일.** 각 섹션 왼쪽 여백에 현재 권의 로마숫자가 sticky로 따라온다. 234KB짜리 문서에서 "내가 지금 어디 있나"를 항상 답해 준다.

기억에 남는 요소는 **등급 배지 체계**다. A/B/E가 문장 안에 인라인으로 박혀서, 읽는 사람이 매 문장마다 "이걸 강의에서 말해도 되나"를 자동으로 판단하게 만든다. 이 사이트의 목적 자체가 그것이다.

## 3. 토큰

### 색

| 토큰 | 다크 | 라이트 | 용도 |
|---|---|---|---|
| `--ink` | `#0a0b0d` | `#f4f1ea` | 캔버스 |
| `--ink2` | `#101216` | `#ebe7de` | 사이드바·인용·코드 |
| `--ink3` | `#161920` | `#e2ddd2` | 입력·표 헤더·칩 |
| `--line` | `#252932` | `#d3ccbd` | 헤어라인 (1px 고정) |
| `--fg` | `#e7e4dd` | `#1a1a18` | 본문 |
| `--fg2` | `#a8a79f` | `#54534d` | 부가 |
| `--fg3` | `#6f6f6a` | `#84837c` | 메타 |
| `--amber` | `#e8a33d` | `#9a6410` | **유일한 강조** |
| `--red` | `#e0614a` | `#a8341c` | 등급 E / 경보 |
| `--green` | `#69a67d` | `#3d6b4c` | 등급 A / 완료 |
| `--blue` | `#6d93c4` | `#2f5484` | 외부 링크 |

라이트 모드는 순백이 아니라 **종이색(`#f4f1ea`)** 이다. 장시간 정독에서 순백은 눈이 아프다.

### 타이포

```
--sans: "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont,
        "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif
--mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, "Cascadia Mono", monospace
```

웹폰트를 못 쓰므로(§4 참조) 차별화는 **스케일과 자간**에서 만든다.

| 요소 | 크기 | 굵기 | 자간 |
|---|---:|---:|---|
| Hero h1 | `clamp(34,4.6vw,58)` | 850 | `-.042em` |
| 권 제목 | `clamp(26,3vw,38)` | 820 | `-.036em` |
| h2 | 24 | 800 | `-.03em` |
| h3 | 17.5 | 750 | `-.024em` |
| 본문 | 16 | 400 | `-.011em` / 행간 1.78 |
| 표 | 13.6 | — | 행간 1.6 |
| 메타(mono) | 10–11 | 600 | `+.1 ~ +.26em` |

**핵심은 대비**다. 한글은 굵기 변화가 라틴보다 덜 드러나므로 850 vs 400처럼 극단으로 벌리고,
mono 메타는 자간을 크게 열어(`+.24em`) 본문과 완전히 다른 질감을 만든다.

본문 폭은 `74ch`. 한글 기준 한 줄 40자 안팎으로, 장문 정독에 맞춘 값이다.

### 간격

8px 배수 대신 **읽기 리듬** 기준: 문단 17px, h3 위 38px, 섹션 위 46px, 권 위 76px.
숫자가 배수로 안 떨어지는 건 의도다. 시각적 등간격이 수치적 등간격보다 우선한다.

## 4. 비타협 요건 — 다시 만들어도 반드시 지킬 것

1. **단일 HTML, 외부 요청 0건.** 폐쇄망 노트북에서 더블클릭으로 열려야 한다. 웹폰트 CDN·외부 스크립트·원격 이미지·fetch 전부 금지.
2. **전역 검색.** `/` 포커스, 실시간 필터, 하이라이트, 일치 개수, `Esc` 해제. 강의 중 이 기능 하나로 산다.
3. **전문 수록.** 요약·발췌 금지. 4,574줄이 다 들어가야 한다.
4. **등급 배지 변환**과 **제목/본문 이모지 구분 규칙** (`MANIFEST.md` §3).
5. **표 우선.** 47개 이상. 가로 스크롤은 표 안에서만, 페이지 본문은 절대 가로 스크롤 금지.
6. **print CSS.** 인쇄해서 들고 들어갈 수 있어야 한다.
7. **날짜 보존.** "2026-07-29 기준" 같은 표기를 디자인상의 이유로 떼지 말 것. 이 문서의 정확성은 날짜에 붙어 있다.

## 5. 다시 만든다면 검토할 만한 방향

현재 안이 최선이라는 뜻은 아니다. 다른 관점으로 가겠다면:

- **편집디자인 계열** — 학술지/화이트페이퍼 조판. 2단 구성, 각주, 판면 여백을 크게. 정독에는 더 나을 수 있으나 검색·스캔에는 불리하다.
- **카드형 대시보드** — 권을 카드로 늘어놓고 진입. 훑기에는 좋지만 **연속 정독이 깨진다.** 이 문서의 주 용도와 상충하므로 권하지 않는다.
- **터미널 계열** — 슬라이드 덱과 톤을 맞춤. 다만 전면 모노스페이스는 한글 장문 가독성이 급격히 나빠진다. 메타에만 제한적으로.
- **라이트 기본** — 형광등 강의장·회의실에서는 라이트가 유리하다. 다크를 기본으로 둔 건 전날 밤 정독을 우선했기 때문이다. **주 사용 환경이 바뀌면 기본값을 뒤집어라.**

## 6. 구현 메모

- 렌더러는 `../build.py`. 이 문서 세트가 실제로 쓰는 마크다운 문법만 지원한다(범용 파서가 아니다).
- 섹션 닫기는 `<!--SECOPEN-->` 마커를 후처리해서 삽입한다. h2 사이를 `<section>`으로 감싸야 검색 필터가 섹션 단위로 동작하기 때문이다.
- 검색은 `p / li / blockquote / .tw / figure.code / h3 / h4`를 블록 단위로 잡고, 블록→섹션→권 순으로 숨김을 전파한다.
- 앵커 id는 `v{권}-{슬러그}` 형태로 권 간 충돌을 막는다. 한글 슬러그를 그대로 쓴다.
- 재빌드: `python3 guide/build.py`
