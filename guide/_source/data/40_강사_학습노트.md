# SBTI 강사 학습노트와 예상 Q&A

조사 기준일: 2026-07-29

## 1. 공부 순서

### 1순위: 수업 전에 반드시 설명할 수 있어야 하는 것

1. 에이전트 루프
   - 목표와 완료 기준
   - 관련 파일 탐색
   - 도구 선택과 실행
   - 결과를 다시 맥락에 넣음
   - 수정·검증·중단 판단

2. 안전한 코드 변경 루프
   - `git status`와 변경 전 상태
   - 계획과 관련 파일 확인
   - 작은 diff
   - 테스트·빌드·진단
   - 사람이 diff를 읽고 승인
   - 실패 시 복구

3. 택가이코드의 실제 운영 경계
   - 택가이Web과 Code의 역할
   - SSO와 API Key가 각각 인증·권한부여하는 범위
   - 사용 가능한 모델과 회차당 예상 동시 요청
   - 프롬프트·응답·도구·오류 로그의 저장 범위와 보존기간
   - Terminal과 VS Code가 공유하는 것과 다른 것
   - 파일·Shell·Git·MCP별 기본 권한

4. 사내 데이터 사용 기준
   - 고객정보·개인정보·운영계 비밀·운영 자격증명 금지 기준
   - 실습에 사용할 정제된 저장소와 문서
   - 화면 캡처·로그·질문 공유 시 마스킹 기준
   - 사고 발생 시 중단·보고·삭제 절차

5. 지식화와 MCP
   - 문서를 프롬프트에 붙이는 것, 검색 지식, 지속 메모리의 차이
   - MCP host/client/server, resource/prompt/tool
   - 로컬 stdio와 원격 Streamable HTTP
   - 서버를 연결했다고 신뢰가 생기는 것은 아님
   - tool description과 `readOnlyHint` 같은 annotation은 권한 보장이 아님

### 2순위: 수업 품질을 올리는 것

- context engineering: 필요한 맥락만, 최신·출처·버전 포함
- rules, knowledge, skills, harness의 차이
- single session, multi-session, multi-agent의 차이
- manager/agent-as-tool과 handoff의 차이
- LSP 진단, 텍스트 검색, 테스트, 빌드가 서로 보완하는 방식
- prompt injection, tool poisoning, dependency hallucination
- Git reflog, restore, revert, bisect의 용도
- worked example, self-explanation, peer review, no-AI transfer 과제

### 3순위: 발표 전날 다시 확인할 변동 정보

- 제품명·현재 제공 표면·라이선스
- 모델명·사용한도·기본 권한

- 택가이코드 도구 개수
- 내부 사용지표와 비용·생산성 수치

- 외부 링크와 스크린샷의 현재 UI

## 2. 핵심 개념

### Agent와 workflow

- workflow: 미리 정한 단계로 실행
- agent: 모델이 도구·순서·분기·중단 중 일부를 동적으로 결정
- 규정 준수와 예측 가능성이 중요하면 workflow가 적합
- 탐색·분해·도구 선택이 중요하면 agent가 유리할 수 있음

### Context engineering

큰 context가 좋은 context는 아니다.

좋은 context에는 다음이 들어간다.

- 목표와 완료 기준
- 관련 파일·오류·문서
- 현재 상태
- 적용할 규칙과 제한
- 이미 실패한 시도
- 검증 방법
- 출처와 버전

관련 없는 전체 저장소·오래된 대화·중복 문서는 attention을 분산시킨다.

### Knowledge, memory, skill, rule

- knowledge: 현재 과업에 검색·참조할 사실
- memory: 여러 과업 사이에 지속되는 정보
- skill: 반복 가능한 작업 절차
- rule: 허용·금지·승인 같은 행동 제약

보안 경계는 문장으로만 적지 않는다. 샌드박스·권한·네트워크 정책·자격증명 격리처럼 실행환경에서 강제해야 한다.

### MCP

- host: 사용자·모델·정책을 조정하는 애플리케이션
- client: host가 한 MCP server와 유지하는 연결
- server: resource, prompt, tool 등을 제공
- stdio: 로컬 프로세스 방식
- Streamable HTTP: 원격/독립 서비스 방식

2026-07-28 MCP 사양은 이전 버전과 비교해 세션·초기화·authorization 세부가 달라졌다. 구현 세부는 반드시 버전을 붙여 말한다. [MCP 2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28), [key changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog)

안전수칙:

- 로컬 MCP 서버는 설치 프로그램처럼 취급
- 신뢰한 서버만 allowlist
- tool 이름·설명·annotation만 보고 안전하다고 판단하지 않음
- 자격증명을 prompt/context/log에 넣지 않음
- 원격 token은 audience와 scope를 제한
- 쓰기·삭제·전송·관리 작업은 별도 승인
- read와 write 도구를 가능한 한 분리

### Multi-agent

장점:

- 독립적인 탐색을 병렬화
- 다른 관점으로 리뷰
- 도메인별 전문화
- 작업 격리

비용:

- token·latency 증가
- 같은 조사를 중복
- 지시와 완료 기준 손실
- 같은 파일 충돌
- 더 큰 권한·공격면

따라서 “여러 개가 더 좋다”가 아니라, 한 agent나 workflow보다 측정 가능한 이점이 있을 때만 사용한다.

### AI 코딩 생산성

안전한 설명:

> AI의 효과는 과업 구조, 경험, 저장소 맥락, 사용 방식, 측정지표에 따라 달라진다. 결과물 수가 늘어도 독립 이해와 디버깅 능력이 같이 늘었다는 뜻은 아니다.

근거:

- METR 연구의 숙련 오픈소스 개발자는 특정 고맥락 과업에서 AI 사용 시 19% 느렸다.
- Microsoft·Accenture·Fortune 100의 무작위 현장실험은 pull request 중심 업무출력이 평균적으로 증가했다고 보고했다.
- 2026년 Anthropic 연구는 낯선 Python 라이브러리 학습에서 AI 사용 집단의 즉시 이해·디버깅 점수가 낮았다고 보고했다.

따라서 수업에서는 결과 코드만 보지 않고 설명, diff, 테스트, 독립 디버깅을 본다.

## 3. 5분 안전 브리핑 초안

> 오늘 실습에서는 제공된 샘플 코드와 문서만 사용합니다. 실제 고객정보, 개인정보, 운영계 데이터, 비밀키, 비밀번호, 토큰, 운영 URL은 입력하지 않습니다.
>
> AI의 답변과 도구 설명은 참고정보입니다. 파일 수정, Shell, Git, MCP, 외부 전송은 서로 위험도가 다르며, 권한을 요청한다고 해서 그 행동이 안전하다는 뜻은 아닙니다.
>
> 실행 전에는 대상 파일과 명령을 읽고, 실행 후에는 diff와 테스트 결과를 확인합니다. 동작하는 코드도 보안·유지보수·라이선스 문제가 있을 수 있습니다.
>
> MCP 서버와 Skill은 연결했다는 이유만으로 신뢰하지 않습니다. 출처와 담당자, 필요한 데이터, 읽기·쓰기 범위, 자격증명, 로그를 확인합니다.
>
> AI는 금융업무 판단의 보조수단입니다. 최종 판단과 책임은 사람에게 있습니다. 이상한 권한 요청, 고객정보 노출, 의심스러운 dependency, 외부 전송이 보이면 실행하지 말고 helper에게 알려주세요.

금융위원회의 2026 금융분야 AI 7대 원칙은 거버넌스, 합법성, 보조수단성, 신뢰성, 금융안정성, 신의성실, 보안성을 제시하고 최종 의사결정과 책임을 임직원이 수행하도록 한다. [금융위원회](https://www.fsc.go.kr/no010101/87142)

## 4. 예상 Q&A

### 도구와 동작

**Q. ChatGPT, Claude, Codex, Cursor, 택가이코드의 차이는?**
A. 일반 대화 UI, 코드 편집기, 터미널 coding agent, 사내 관리·권한·로그 체계가 각각 다르다. 브랜드보다 실행 위치, 보는 데이터, 사용할 도구, 승인 방식, 검증 절차로 비교한다.

**Q. 에이전트는 코드를 자동으로 바꾸나요?**
A. 도구와 권한 설정에 따라 가능하다. 읽기·제안·쓰기·실행을 분리하고, 쓰기 뒤에는 diff와 테스트를 확인해야 한다.

**Q. Terminal과 VS Code 중 무엇을 쓰나요?**
A. 프로젝트 루트·Shell·Git 중심이면 Terminal이 직관적이고, 파일·진단·diff를 눈으로 보며 작업하면 VS Code가 편하다. 같은 엔진이라는 내부 설명의 정확한 범위는 제품 담당자에게 확인한다.

**Q. 모델이 틀리면 어떻게 하나요?**
A. 재현 가능한 기대값을 적고, 관련 파일과 근거를 찾고, 작은 가설 하나를 테스트한다. 같은 모델의 자기확신보다 테스트·빌드·로그·동료 리뷰가 강한 증거다.

### Skills·Knowledge·MCP

**Q. Skill과 MCP의 차이는?**
A. Skill은 반복 작업 절차이고, MCP는 외부 데이터·도구 시스템을 연결하는 프로토콜이다.

**Q. 지식화하면 모델이 학습되나요?**
A. 보통 모델 가중치를 다시 학습한다기보다 문서를 파싱·검색해 현재 대화 context에 넣는다. 저장·색인·갱신·삭제 방식은 제품 구현을 확인해야 한다.

**Q. MCP 서버를 추가하면 바로 안전하게 쓸 수 있나요?**
A. 아니다. 서버 출처, owner, 권한, 데이터, token, tool 범위, 로그, prompt injection 가능성을 검토해야 한다.

**Q. `readOnlyHint`가 있으면 읽기 전용인가요?**
A. MCP specification에서 annotation은 힌트이지 보안 통제가 아니다. 신뢰한 서버와 실제 authorization이 필요하다.

**Q. 문서가 오래됐거나 서로 충돌하면?**
A. 출처·작성일·버전을 같이 보여주고, 충돌을 숨기지 않는다. 최신 owner 문서를 우선하되 업무 규정의 권위 체계를 따른다.

### 멀티에이전트

**Q. 여러 agent를 쓰면 무조건 더 좋은가요?**
A. 아니다. 독립적인 탐색·비교·리뷰에는 유리하지만 비용·지연·중복·충돌이 늘어난다. 한 agent로 충분한 일은 single이 낫다.

**Q. 같은 파일을 동시에 바꾸면?**
A. 담당 범위를 나누거나 별도 branch/worktree를 사용한다. 하나의 작업을 여러 agent가 동시에 쓰게 두지 않는다.

### 보안과 금융권 사용

**Q. 운영 코드나 고객정보를 넣어도 되나요?**
A. 내부 정책에서 명시적으로 승인한 범위가 아니라면 안 된다. 수업에서는 정제된 샘플만 사용한다.

**Q. API Key는 어디에 넣나요?**
A. 승인된 비밀 저장소·환경변수·제품 설정을 사용하고, prompt·source file·screenshot·채팅·로그에 붙이지 않는다.

**Q. 로그에는 무엇이 남나요?**
A. 택가이Web/Code의 현재 구현과 내부 보존정책을 확인해 답해야 한다. 질문, 응답, 도구 인자·결과, 오류, 파일명, 사용자정보 각각을 구분한다.

**Q. AI가 만든 dependency를 설치해도 되나요?**
A. 패키지 존재, 공식 registry, owner, version, license, 취약점과 유지상태를 확인하기 전에는 설치하지 않는다.

**Q. prompt injection은 코딩에서도 생기나요?**
A. 생긴다. 저장소 문서, 이슈, dependency, MCP tool 설명이나 검색 결과가 모델에 행동을 지시할 수 있다. 외부 텍스트를 명령으로 신뢰하지 않는다.

### 수치와 제품상태

**Q. 87.5% 단축은 어떻게 계산했나요?**
A. 수업 전에 대상 화면 수, 기존/AI 방식 MM, 포함·제외 작업, 측정자, 최대값/평균 여부를 준비한다. 근거가 없으면 “단일 내부 POC에서 관찰한 최대값” 이상으로 일반화하지 않는다.

**Q. 17억~90억은 확정 절감인가요?**
A. 슬라이드상 추정치다. 감사·결재 확정 절감과 같은 수준으로 말하지 않는다.

**Q. 37개인가요, 50개 이상인가요?**
A. 제품 버전이 다르면 inventory가 달라질 수 있다. 교육에 배포할 빌드에서 직접 도구 목록을 출력해 기준일과 함께 답한다.

**Q. ChatGPT 앱이 Codex로 개명됐나요?**
A. 반대 방향에 가까운 한정된 전환이다. 이전 Codex desktop app이 새 ChatGPT desktop app으로 이동했고, 그 안에 Codex가 별도 view로 남는다. Codex 전체가 ChatGPT로 개명된 것은 아니다. [OpenAI migration notice](https://help.openai.com/en/articles/20001276-moving-to-the-new-chatgpt-desktop-app)

**Q. “가장 많이 쓰는” 도구인가요?**
A. 현재 자료에는 비교 가능한 시장점유율 근거가 없다. “대표적인 예”라고 말하는 것이 안전하다.
