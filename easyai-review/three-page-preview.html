AI가 도구를 쓰는 순서

모델이 파일이나 터미널을 직접 조작하는 것이 아닙니다. 모델이 도구 사용을 요청하면, 하네스가 권한을 확인하고 실제 작업을 실행한 뒤 결과를 다시 모델에게 전달합니다.

  1. 1. 요청

    사용자가 목표와 작업을 요청합니다.

  2. 2. 안전 확인

    허용된 도구·권한·규칙을 확인합니다.

  3. 3. 도구 실행

    하네스가 파일·터미널 같은 도구를 실행합니다.

  4. 4. 결과 전달

    실행 결과를 모델이 읽을 입력으로 돌려줍니다.

  5. 5. 다음 판단

    계속할지, 수정할지, 끝낼지 선택합니다.

싱글은 빠르게,
멀티는 역할을 나눠서

멀티에이전트의 핵심은 에이전트 수가 아닙니다. 작업을 독립된 역할과 관점으로 나누고, 결과를 다시 모았을 때 품질이나 속도가 실제로 좋아지는지가 기준입니다.

SINGLE AGENT

한 흐름으로 빠르게

  • 질문과 짧은 확인
  • 단일 파일 수정
  • 단계와 범위가 분명한 작업
VS
MULTI-AGENT

역할과 관점을 나눠서

  • 작성과 검토를 독립적으로 분리
  • 서로 다른 관점을 나란히 비교
  • 넓은 범위를 여러 갈래로 탐색
1
리뷰

작성 담당과 검토 담당을 분리해 같은 실수를 반복할 가능성을 낮춥니다.

2
비교

서로 다른 기준으로 답을 만든 뒤 차이와 근거를 함께 봅니다.

3
찾기

큰 자료나 코드 범위를 나눠 동시에 탐색하고 결과를 합칩니다.

주의 · 멀티에이전트가 항상 더 좋은 것은 아닙니다. 역할을 나눴을 때 측정 가능한 이점이 있을 때만 사용합니다.

AI가 궤도를 이탈하지 않게 만드는 시스템

하네스 엔지니어링은 AI 에이전트가 정해진 범위 안에서 실제 작업을 수행하고, 결과를 확인하며, 필요하면 다시 시도하도록 작업 환경·권한·검증 절차를 설계하는 기술입니다.

PROMPT무엇을 시킬지
CONTEXT이번 요청에서 무엇을 보여 줄지
HARNESS어떻게 실행하고 검증·재시도할지
1. 규칙·지식

프로젝트 지침, 참고 문서, 이전 작업 상태를 필요한 순간에 구성합니다.

2. 도구·권한

파일과 터미널을 연결하고 허용·확인·차단으로 실행 범위를 통제합니다.

3. 검증·피드백

테스트·빌드 결과를 다시 전달해 실패하면 수정하고 재시도합니다.

정확성 메모 · 이 구분은 이해를 위한 단순화입니다. 실제 하네스는 모델에 전달할 컨텍스트를 구성하고 관리하는 일도 함께 담당합니다.
