LLM 심판: 평가 편향을 구체적으로 설명

생소하고 범위가 모호한 표현을 평가 편향과 일관성 문제로 풉니다.

용어 통일
기존 문구
여기에 Debate(토론·교차평가)를 더해 5패턴으로 세기도 합니다. 여러 에이전트가 독립 답을 내고 서로 반박·채점(LLM-as-judge)하게 하는 방식. 단, 심판 모델은 채점 기준이 슬금슬금 변하는 캘리브레이션 드리프트가 있어 주기적 인간 검증이 필수입니다.
추천 문구

필요하면 토론·교차평가를 별도 패턴으로 더할 수 있습니다. 여러 에이전트가 독립 답을 내고 서로 검토하거나, 평가 모델이 점수를 매깁니다. 다만 LLM 심판은 답변 순서 같은 입력 형식에 따라 판단이 달라질 수 있으므로, 평가 기준표와 사람의 표본 검수를 함께 둡니다.

바꾼 이유LLM-as-a-judge 연구에서는 위치 편향과 판단 일관성 문제가 직접 관찰됩니다. “캘리브레이션 드리프트”보다 구체적입니다. 출처 7

git worktree: “격리된 사본” 표현 수정

워크트리는 복제본이 아니라 같은 저장소에 연결된 별도 작업 트리입니다.

꼭 수정
기존 문구
파일 충돌의 정답 한 줄: git worktree add — 같은 저장소의 별도 작업 디렉터리를 파서 에이전트마다 격리된 사본에서 일하게 하는 것.
추천 문구

git worktree add -b <브랜치> <경로>는 같은 저장소에 연결된 별도 작업 디렉터리와 브랜치를 만듭니다. 에이전트별 작업 공간을 나누는 데 유용하지만 충돌을 자동으로 없애지는 않으므로, 담당 파일과 병합 순서도 함께 정해야 합니다.

바꾼 이유Git 공식 용어는 “linked worktree”이며 저장소 데이터를 공유합니다. 같은 줄을 바꾸면 병합 충돌은 여전히 생깁니다. 출처 6

MCP·A2A: 연결 대상과 범위 분리

MCP는 AI 앱-외부 시스템, A2A는 독립 에이전트 시스템 사이를 다룹니다.

용어 통일
기존 문구

MCP = 에이전트 ↔ 도구/데이터를 연결하는 표준 규격(host/client/server, tools/resources/prompts).

A2A = 에이전트 ↔ 에이전트 통신 규격(Linux Foundation).

추천 문구

MCP(Model Context Protocol) = AI 애플리케이션이 외부 도구·데이터·재사용 프롬프트를 발견하고 사용할 수 있게 하는 개방형 프로토콜입니다. host/client/server 구조를 사용합니다.

A2A(Agent2Agent Protocol) = 서로 다른 에이전트 시스템이 기능을 발견하고 작업을 주고받도록 하는 에이전트 간 상호운용 프로토콜입니다. Google이 시작했고 현재 Linux Foundation이 관리합니다.

A2A는 한 제품 내부의 서브에이전트 호출 방식을 정하는 규격은 아닙니다.

바꾼 이유MCP 공식 문서는 범위를 “AI 애플리케이션의 컨텍스트 교환”으로 설명하고, A2A는 독립 에이전트 시스템 간 상호운용을 다룹니다. 출처 3 · 출처 5

USB-C 비유: 호환성과 권한 조건 추가

“꽂으면 어떤 에이전트든 사용”이라는 자동 연결 오해를 막습니다.

쉬운 설명
기존 문구
쉽게 말하면 MCP는 USB-C 포트입니다. 도구마다 전용 케이블을 만들지 않고, 규격에 맞춰 꽂으면 어떤 에이전트든 그 도구를 씁니다. 단, 아무 USB나 꽂으면 안 되듯 MCP 도구 설명에 명령을 심는 공격(tool poisoning)도 존재 — 신뢰할 수 있는 서버만.
추천 문구

쉽게 말하면 MCP는 AI 앱에 공통 연결 단자를 마련하는 것과 비슷합니다. MCP를 지원하는 앱은 서버가 공개한 도구와 자료를 같은 방식으로 찾을 수 있지만, 실제 사용 범위는 서로 지원하는 기능과 권한 설정에 달려 있습니다. 연결 전에는 서버 출처, 요청 권한, 실행 내용을 확인하고 최소 권한으로 허용합니다. 신뢰하지 않는 서버와 도구 설명도 그대로 믿지 않습니다.

바꾼 이유MCP도 기능 협상과 권한 승인이 필요합니다. 공식 보안 지침은 서버 프로세스 격리와 최소 권한을 권고합니다. 출처 3 · 출처 4
