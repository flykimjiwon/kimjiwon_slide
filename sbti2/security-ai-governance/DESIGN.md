# 택가이웹 × 택가이코드 보안·AI 거버넌스 장표 디자인 시스템

## 0. 이번 개정의 시각 계약

- 사용자 제공 레퍼런스: `택가이 플랫폼 구조` 장표
- 적용 범위: `index.html`, `loop.html`, 두 최종 PNG
- 레퍼런스에서 가져올 요소: 중앙 정렬 제목, 번호형 3구역 구조, 얕은 테두리, 파랑/초록 역할 구분, 선형 2D 아이콘, 짧은 기능 설명, 하단 원칙 스트립
- 적용하지 않을 요소: 레퍼런스의 제품명·Phase 문구를 그대로 복사하거나 현재 장표의 내용을 단순 축약하는 방식
- 금지: 3D 렌더, 유광 오브젝트, 사진형 보조 이미지, 과도한 글로우·그림자, 광고 문구처럼 들리는 제목

## 1. 목적과 독자

- 산출물: 사내 보안성·AI 거버넌스 제출용 16:9 장표 이미지 2종
- 1장: 택가이웹과 택가이코드의 중앙 관리·실행 통제 연동 구조
- 2장: 택가이코드의 LLM·Harness·Tool 반복 실행 구조
- 주 독자: 보안성·AI 거버넌스 검토자. 30초 안에 시스템 경계, 전달 정보, 통제 지점을 파악할 수 있어야 합니다.
- 보조 독자: 발표자와 개발자. 문구와 구조를 HTML에서 직접 수정할 수 있어야 합니다.

## 2. 문장과 설명 방식

- 제목은 구조를 설명하는 명사형으로 씁니다.
  - `택가이코드 보안·AI 거버넌스 구조`
  - `택가이코드 LLM·Tool Calling 실행 구조`
- 부제는 한 문장으로 구성 요소와 책임을 설명합니다.
- 패널 제목은 `제품명 (역할)` 형식으로 씁니다.
- 흐름 라벨은 전달되는 데이터만 적습니다. 예: `API Key · 모델 정책`, `사용량 · 오류 로그`.
- 본문은 기능명 1줄 + 사실 설명 1줄을 기본으로 하며, 검증되지 않은 효과·절대 표현을 쓰지 않습니다.

## 3. 컬러 토큰

실제 구현 정본은 두 장표가 함께 불러오는 `tokens.css`입니다.

| 역할 | 토큰 | 값 | 용도 |
|---|---|---:|---|
| Canvas | `--color-canvas` | `#fbfdff` | 흰색 기반 장표 배경 |
| Surface | `--color-surface` | `#ffffff` | 패널·목록 표면 |
| Text | `--color-ink` | `#071939` | 제목과 핵심 문구 |
| Muted | `--color-muted` | `#53627a` | 보조 설명 |
| Line | `--line-default` | `#d8e4f2` | 얕은 구획선 |
| Web blue | `--color-web` | `#1767e8` | 택가이웹·정책·LLM 판단 |
| Code green | `--color-code` | `#16945b` | 택가이코드·허용 실행·결과 |
| Harness navy | `--color-harness` | `#153665` | 하네스·Tool 실행 통제 |
| Warning | `--color-warning` | `#d45b24` | 실행 전 검증 강조 |

파랑은 중앙 관리와 판단, 초록은 클라이언트와 정상 실행, 네이비는 하네스·도구 실행을 뜻합니다. 색만으로 의미를 구분하지 않고 번호·제목·아이콘을 함께 둡니다.

## 4. 타이포그래피와 밀도

- Primary: `-apple-system, BlinkMacSystemFont, "SF Pro Display", "Pretendard", "Segoe UI", sans-serif`
- Mono: `"SFMono-Regular", "JetBrains Mono", Menlo, monospace`
- 제목: 56px / 900 / 1.08, 한 줄 유지
- 부제: 18px / 700 / 1.45, 최대 한 줄
- 패널 제목: 22px / 850
- 기능명: 15–17px / 800
- 설명: 12–14px / 650–720
- 모든 한글 블록은 `word-break: keep-all`을 사용합니다.

## 5. 캔버스와 재사용 프리미티브

- 고정 캔버스: 1672 × 941px
- 바깥 여백: 좌우 38px, 상단 30px, 하단 30px
- 구조: 헤더 → 번호형 3구역 맵 → 보안·통제 원칙 스트립
- 시각 깊이: 1px 테두리, 12–18px 반경, 매우 얕은 그림자만 사용합니다.

### NumberedPanel

- 번호 셀 + 제목 셀로 구성한 헤더와 흰색 본문을 사용합니다.
- `client`, `web`, `harness`, `input`, `loop`, `tool` 변형은 헤더와 테두리 색만 바꿉니다.

### TransferLane

- 두 패널 사이에 양방향 화살표와 전달 정보 2줄을 둡니다.
- 정책·요청은 진행 방향, 사용량·오류·결과는 반환 방향으로 표시합니다.

### FlatDiagram

- 실제 화면을 복제하지 않고 사이드바·통계·차트·로그를 단순 사각형과 선으로 표현합니다.
- 최종 산출물에는 래스터 보조 이미지를 사용하지 않습니다.

### FeatureRow

- 2D 선 아이콘, 기능명, 설명을 한 줄 구조로 배치합니다.
- 아이콘 크기와 선 굵기는 모든 패널에서 동일합니다.

### PrincipleStrip

- 왼쪽 제목 블록 + 동일 폭의 네 원칙으로 구성합니다.
- 각 원칙은 아이콘, 명사형 제목, 사실 설명을 포함합니다.

## 6. 장표별 정보 구조

### 거버넌스 장표

1. `택가이코드 (클라이언트)` — Terminal·VS Code, 개인 API Key 사용
2. `택가이웹 (중앙 관리)` — SSO, API Key, 승인 모델·권한, 보안 필터, 사용량·오류·감사 로그
3. `택가이코드 하네스 (실행 통제)` — LLM 판단과 Harness 실행 통제 분리, Tool 실행 전 검증

### 실행 루프 장표

1. `요청·컨텍스트 입력` — 목표·완료 조건, 규칙·코드·Tool 정보
2. `LLM + 하네스 (반복 제어)` — 컨텍스트 구성, 다음 행동 판단, Tool Call 검증, 결과 관찰, 완료 판단
3. `Tool 실행 환경` — File·Search·Shell·Git·MCP·Test 실행과 결과 반환

루프는 `미완료 → 결과를 컨텍스트에 추가 → 다음 판단`, `완료 → 사용자 보고`의 두 출구를 명시합니다.

## 7. 접근성·검수 기준

- 1672 × 941에서 모든 문구가 잘리지 않아야 합니다.
- 한글 어절·조사·술어가 부자연스럽게 분리되지 않아야 합니다.
- 색상 대비는 WCAG AA 이상을 목표로 합니다.
- 아이콘은 장식용 이모지가 아니라 동일 선 굵기의 SVG를 사용합니다.
- 모든 정보는 실제 DOM 텍스트와 SVG로 구성하고, 전체 화면을 이미지로 붙이지 않습니다.
- 고정 캔버스는 장표 삽입 목적의 의도된 제약이며, 브라우저에서는 비율을 유지해 축소합니다.

## 8. 주장 경계와 디자인 부채

- 덱에 이미 명시된 SSO, 개인 API Key, 모델·권한·사용량 관리, PII 보안 필터, 사용량·오류·감사 로그, 도구 실행 전 안전 확인만 사용합니다.
- 사용자 실명, 부서명, 운영 수치, 실제 보안 구조 상세는 넣지 않습니다.
- `완전 차단`, `무결성 보장` 같은 검증되지 않은 절대 표현을 사용하지 않습니다.
- 정적 장표이므로 키보드 상호작용·모션 상태는 없습니다. 이 제한은 제출 포맷에 따른 의도된 범위입니다.
